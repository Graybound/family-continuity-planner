# Backup format

Backups are UTF-8 JSON files named `family-continuity-backup-YYYY-MM-DD.json`. They are readable in any text editor, so a family can recover information even without the app.

## Version 2 (current)

```json
{
  "schema": "family-continuity-planner",
  "schemaVersion": 2,
  "info": {
    "planName": "The Morgan Household (sample)",
    "region": "Exampleville",
    "trustedContact": "Pat Lee, neighbor, 555-0140",
    "createdAt": "2026-11-01T12:00:00.000Z",
    "updatedAt": "2026-11-01T12:00:00.000Z",
    "lastReviewedAt": "2026-11-01",
    "lastExportedAt": "2026-11-01T12:00:00.000Z",
    "isSample": true
  },
  "preferences": { "privacyDefault": false, "includePrivateInPrint": false },
  "startHere": { "mode": "default", "customText": "" },
  "messages": [{ "id": "r1", "audience": "Jordan", "title": "For you first", "body": "..." }],
  "records": {
    "responsibilities": [], "people": [], "contacts": [], "health": [], "home": [],
    "accounts": [], "documents": [], "plans": [], "notes": []
  },
  "checklist": [{ "id": "r2", "group": "First 24 hours", "title": "...", "note": "", "due": "", "done": false }],
  "modules": { "health": "review-later" },
  "assessment": { "areas": { "taxes": "mostly-me" }, "risks": ["bills"], "completedAt": "ISO time" },
  "audit": { "dismissed": ["no-contacts"], "deferred": { "backup-old": "2026-12-01" } },
  "activity": [{ "id": "r3", "text": "Added person", "at": "ISO time" }],
  "exportedAt": "ISO time",
  "exportedBy": "Family Continuity Planner 0.2.0"
}
```

A complete example: [examples/sample-plan.json](../examples/sample-plan.json).

### Rules

- `exportedAt` and `exportedBy` are informational and ignored on import.
- Plan details live in `info`, not `meta` as in version 1. This is deliberate: the version 1 app accepted any file with a `meta` object and a `checklist` array, and would have "restored" a version 2 file while silently dropping every record. Without `meta`, version 1 rejects the file with an error instead.
- Dates without times are `YYYY-MM-DD`. Times are ISO 8601.
- Every record value is a string. Unknown fields are dropped with a warning.
- IDs match `^[A-Za-z0-9_-]{1,64}$` and are unique across the whole plan. Others are replaced.
- Text fields are limited to 20,000 characters (messages and Start Here to 100,000). Control characters other than tab and newline are removed.
- Up to 5,000 records per section and 5,000 checklist items.
- `modules` values: `completed`, `review-later`, `not-applicable`. Missing means automatic.
- `assessment.areas` keys: `finances, household, technology, maintenance, vehicles, taxes, insurance, children, pets, healthcare, coordination, work, records, digital`. Values: `mostly-me, shared, someone-else, not-applicable`.
- `assessment.risks` values: `bills, autopay, taxes, investments, insurance, access, internet, photos, maintenance, seasonal, vehicles, children, pets, healthcare, business`.

### Record fields by section

Field keys are defined in [src/core/sections.ts](../src/core/sections.ts). Fields marked (P) are private: hidden in privacy mode and withheld from print unless chosen.

| Section key | Fields |
|---|---|
| `responsibilities` | name, domain, frequency, owner, backupPerson, howItWorks, recordsLocation (P), whoCanHelp, guidance, notes |
| `people` | name, relationship, phone, email, address (P), needs, notes |
| `contacts` | name, role, priority, phone, email, instructions |
| `health` | person, recordType, name, details (P), phone, instructions (P) |
| `home` | name, type, provider, account (P), phone, location (P), instructions |
| `accounts` | name, type, owner, identifier (P), website, phone, access (P), notes (P) |
| `documents` | name, category, owner, location (P), expires (date), notes (P) |
| `plans` | name, trigger, lead, backup, meetup (P), steps, reviewed (date) |
| `notes` | name, category, details (P), reviewed (date) |

## Version 1 (original single-file app)

Recognized by `"version": 1` (or no `schema` marker) with a `meta` object and a `checklist` array. Sections are top-level arrays. Example: [examples/legacy-v1-backup.json](../examples/legacy-v1-backup.json), generated by the original app.

### Migration from version 1

| v1 | v2 |
|---|---|
| `meta.householdName` | `info.planName` |
| `meta.region`, `meta.trustedContact`, `meta.createdAt`, `meta.updatedAt` | same names in `info` |
| `meta.privacyDefault` | `preferences.privacyDefault` |
| `meta.includePrivatePrint` | `preferences.includePrivateInPrint` |
| `meta.meetup` (if not empty) | a note titled "Household meeting point" |
| `people`, `contacts`, `health`, `home`, `accounts`, `documents`, `plans`, `notes` | `records.<same key>`, field keys unchanged |
| `checklist`, `activity` | unchanged |
| (none) | `records.responsibilities`, `messages`, `startHere`, `modules`, `assessment`, `audit` start empty |

The migration is reported in the restore preview. The version 1 app refuses version 2 files with an error (tested in `tests/e2e`).

## Rejected files

Not JSON, empty, over 10 MB, a JSON array or primitive, a different `schema`, an unknown shape, or a `schemaVersion` newer than the app supports. In every case the current plan is left untouched and the message says why.
